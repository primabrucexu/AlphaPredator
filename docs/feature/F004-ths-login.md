## What
用户通过手工编写 `data/ths_credentials.json` 配置同花顺账号和密码。AlphaPredator 不提供网页配置入口；后续网页行情请求和后台任务统一从该文件读取正式账号。程序不显式传入 MAC，由 thsdk 按账号生成默认派生 MAC。

第一版范围：

- 用户手工创建或修改 `data/ths_credentials.json`。
- 不读取机器网卡 MAC，也不显式向 thsdk 传入 MAC；统一使用 thsdk 根据账号生成的默认派生 MAC。
- 文件格式固定为现有的 `username`、`password` 两个非空字符串字段。
- 正式账号登录必须从该文件读取配置；Web 进程和后台 Worker 不得维护独立的账号来源。
- 配置文件不存在时视为未配置正式账号，保留 thsdk 游客账号行为。

第一版非目标：

- 不提供网页表单、API 或其他程序化方式创建和修改账号密码文件。
- 不加密本地账号密码文件。
- 不提供手工指定 MAC 的兼容入口。
- 不提供多账号管理或运行时自动监听文件变化。

## How
### 配置与验证流程

1. 用户按照 README 手工创建 `data/ths_credentials.json`，写入账号和密码。
2. `ThsdkMarketDataProvider` 建立连接前通过统一配置加载入口读取文件，并校验 JSON 结构及非空字段。
3. 后端只使用文件中的账号和密码创建 thsdk 客户端，不传入 MAC，由 SDK 使用默认派生 MAC 执行真实连接。
4. 文件格式错误、字段缺失或 thsdk 登录失败时返回明确错误，不修改用户文件，也不生成伪造配置。
5. 用户修改配置文件后重启后端，使 Web 进程和独立 Worker 重新读取配置。

### MAC 策略

- 不读取或校验运行机器的真实网卡 MAC。
- 验证连接和创建 Provider 时只向 thsdk 传入 `username`、`password`，由当前锁定的 thsdk 版本按账号生成默认派生 MAC。
- 派生 MAC 不在配置文件中持久化，也不在 API 和日志中展示完整值。
- Web 和 Worker 必须使用相同的账号输入方式，禁止一处传入真实 MAC、另一处使用 SDK 默认值。

### 配置读取与架构边界

- 行情业务仍然只通过 `MarketDataProvider` 获取数据。
- `ThsdkMarketDataProvider` 创建 thsdk 客户端前必须通过统一配置加载入口读取 `data/ths_credentials.json`，并且不得显式传入 MAC。
- Web API 使用的 Provider 与股票目录后台任务通过同一个配置加载入口读取文件，避免两套账号配置逻辑。
- thsdk 客户端的创建、重连、关闭和异常适配继续位于 `backend/app/market_data/provider/`。
- 配置文件位于现有 Git 忽略的 `data/` 目录，不进入版本控制。
- 根目录 `README.md` 说明手工配置步骤、文件路径、固定 JSON 格式、重启要求和敏感信息注意事项。
- AlphaPredator 不提供账号密码配置页面或文件写入 API，正式账号不再通过环境变量配置。

## Risk

| 风险 | 解决 |
|------|------|
| 账号密码以明文保存在本机 | 这是个人本地应用第一版的已确认取舍；文件放在 Git 忽略的 `data/` 目录，API 和日志不得返回密码 |
| 用户写入无效 JSON 或遗漏字段 | 加载时严格校验并返回明确错误，不修改原文件，也不静默改用其他正式账号来源 |
| thsdk 升级后默认派生 MAC 规则变化 | 锁定并验证 thsdk 版本；升级前重新执行正式账号登录和并发探针 |
| Web 和 Worker 使用不同 MAC 策略导致登录行为不一致 | 两个进程统一只传账号密码，禁止显式传入真实或手工 MAC |
| Web 进程和后台任务读取到不同配置 | 统一配置加载入口，并要求修改文件后重启后端及 Worker |
