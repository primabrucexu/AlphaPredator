## What

### 已确认需求

- 按选股规则文档已确认的信号、买入、持有、卖出和无法成交处理，在历史区间内进行确定性模拟。
- 支持两种回测模式：个股回测和全市场组合回测。
- 个股回测针对一只股票按时间顺序执行规则，不设置跨股票的资金竞争，用于观察该股票的交易和收益表现。
- F006.4 的“模式选股”页面在股票命中当前信号后自动调用个股回测，不再要求用户逐只输入日期区间；旧个股回测任务及其买入、分次卖出、收益、待成交和未平仓详情继续可查看。
- 全市场组合回测按历史交易日扫描规则适用股票，使用一个资金账户处理多个股票的信号、订单、持仓、卖出和净值。
- 两种模式复用同一规则版本、指标、选股判定和买卖条件，不复制实现另一套规则公式。
- 回测只读取信号生成时点已经可获得的数据，禁止未来数据泄漏。
- 具体策略是否计算佣金、税费和滑点由规则文档定义；SR001 第一版只按股票价格变化计算收益。
- 回测是按规则文档对历史价格数据执行的确定性计算模型，不代表真实市场交易行为，也不保证真实订单可申报或成交。
- 规则可以定义同一根 K 线既判断条件又按该 K 线价格成交，以及在整个历史区间使用统一模型而不随历史交易制度变化；此类假设必须记录在规则和结果中。
- 回测引擎支持规则定义的部分卖出、剩余仓位、止盈、止损、技术退出、T+1 约束和退出优先级。

### 第一版非目标

- 不连接券商，不创建真实订单，不提供实盘或模拟盘交易。
- 不自动优化参数，不搜索最佳规则，不根据回测结果自动修改规则。
- 不由 Agent 或运行时解释 Markdown 生成交易逻辑。
- 不在 Web 或 MCP 进程中直接读取 DuckDB。

### 待确认事项

- 全市场组合回测的初始资金、每笔仓位、最大持仓数和信号超过可用仓位时的选择顺序。
- 任务和子任务如何拆分，确保跨日持仓与账户状态连续且符合 F002 统一执行路径。
- 回测结果在 SQLite 中的持久化结构、保留周期和迁移方案。
- 全市场组合模式的页面输入、净值和结果对比范围。
- 个股与全市场模式的完整统计指标。

### 统一成交基础约束

- 回测直接复用 F006.1 生成的有效日 K 序列，不重新定义或过滤另一套指标日期。
- “可买入日 K”和“可卖出日 K”首先必须是有效日 K，再应用规则定义的一字板、信号锁定及其他成交限制。
- 所有 A 股规则统一遵守 T+1：实际买入日 B 不允许卖出，最早只能在 B 后的交易日成交卖单。
- T+1 只限制卖出成交；退出条件是否允许在 B 日观察和锁定，由规则明确，但即使产生信号也不得在 B 日成交。
- 停牌、无有效日 K 或规则定义的不可成交状态不会消耗持仓，也不会伪造成交；等待期限和顺延价格由规则定义。
- 规则中的 `B+1`、`B+2` 等有效日 K 偏移沿用 F006.1 序列；市场交易日期和有效日 K 序号必须分别记录，不能混用。

### 个股回测

- 输入至少包含规则编号、规则版本、股票、开始日期和结束日期。
- 同一只股票的信号和交易按时间顺序处理。
- 输出至少能够区分已完成交易、未成交和回测结束仍未平仓的交易。
- 同一交易存在多次卖出时，逐笔记录卖出原因、数量、价格和已实现收益，并保留剩余仓位状态。
- 单笔收益使用规则文档定义的实际买卖价格计算。

### 全市场组合回测

- 输入至少包含规则编号、规则版本、历史区间和资金/仓位参数。
- 按交易日处理当日信号、可成交订单、卖出、现金和持仓。
- 同一天信号超过可用资金或仓位时必须使用已确认且可复现的选择规则，不得依赖无序结果。
- 输出账户现金、持仓、交易、每日净值和组合统计。

### 共同边界

- DuckDB 只由 Worker 打开和读取。
- 规则 Evaluator、指标口径和规则版本来自 F006.1 与对应规则定义。
- 回测结果记录规则版本、实际参数、历史区间和回测模式。
- 回测结果记录影响成交的模型假设，包括同 K 线成交、T+1、费用、滑点、部分卖出和历史制度口径。
- 数据缺失、无法成交、未成交和计算失败使用不同状态，不生成伪造交易。

## Implementation

- 个股回测状态机位于 `backend/app/screening/backtest.py`，按有效日 K 顺序向规则会话提供截至当日的历史前缀。
- 引擎统一维护单一活动持仓，执行 T+1、部分卖出、剩余仓位、已实现收益、未成交和未平仓结果语义。
- `individual_backtest` Handler 只生成一个子任务，由 Worker 读取 DuckDB 并写回 SQLite 任务结果。
- F006.3 的 SR001 revision 1 已接入个股回测会话，并复用同一 MACD 与选股判定实现。
- `POST /api/tasks/individual-backtest` 继续提供独立个股回测能力；`/screening` 已由 F006.4 改为命中后自动回测，旧独立任务仍可在 `/screening/tasks/{task_id}` 查看交易、收益、待成交和未平仓结果。
- 个股回测作为 `COMPUTE` 任务自动归入“模式选股”；数据更新类 `EXCLUSIVE_UPDATE` 任务保留在通用“任务”页面。
- 第一版 MCP 只通过 F006.4 间接复用个股回测，不新增 F006.2 通用或独立回测 Tool。
- 全市场资金账户、跨日组合状态和专用持久化结构尚未实现，因此 Feature 状态保持“部分完成”。

## Risk

| 风险 | 解决 |
|---|---|
| 个股收益简单相加被误当成组合收益 | 个股和全市场模式使用独立结果类型，全市场必须模拟资金与持仓 |
| 跨日状态与 F002 子任务边界冲突 | 实现前单独确认任务拆分和状态持久化方案 |
| 使用未来行情判断历史成交 | 明确每个信号和成交的可用时点，并建立时间隔离测试 |
| 理想化成交被误解为真实可执行性 | 规则和结果明确标记纯数据模型及具体成交假设 |
| 涨跌停、停牌或数据缺失生成伪造成交 | 按规则定义顺延或标记未成交，不做隐式成交 |
