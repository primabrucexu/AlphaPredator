# Feature Doc 标准模板

## 模板内容

```markdown
# F{NNN}: {Feature Name}
> STATUS：{当前功能状态}

## MileStone

| 日期         | 事件   |
|--------------|--------|
| {YYYY-MM-DD} | {立项} |

## Relation
- **Evolved from**: {F0xx}（{说明}）
- **Blocked by**: {F0xx}（{说明}）
- **Related**: {F0xx}（{说明}）

## What
{用户想要什么}

## How
{怎么做}

## Acceptance Criteria
- [] ACx: {验收条件}


## Risk

| 风险       | 解决       |
|------------|------------|
| {风险描述} | {解决方案} |
```
---
## 模板说明

| 模块                | 必选 | 说明                                                         |
| ------------------- | ---- | ------------------------------------------------------------ |
| 标题                | 是   | 固定格式为 F{NNN}: {Feature Name}                            |
| status              | 是   | 可选状态：设计、WIP、完成                                    |
| MileStone           | 是   | 时间线倒序经过，比如：2020-01-01 提出需求，2020-01-02 完成初始设计 |
| Relation            | 否   | 和其他需求的关系                                             |
| What                | 是   | 用户想要一个什么功能，通常还要包含用户期望怎么使用           |
| How                 | 是   | 需要怎么做                                                   |
| Acceptance Criteria | 是   | 验收条件                                                     |
| Risk                | 否   | 比如某个功能涉及多种需要决策的内容，这里要体现用户的决策     |
