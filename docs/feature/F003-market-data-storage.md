## What

### 已确认需求

- 从 thsdk 获取全市场 A 股前复权日 K，并保存到 DuckDB，用于加速后续回测、选股和技术指标计算。
- 首次更新覆盖本地股票目录中的全部 A 股，每只股票固定从 `2025-01-01` 开始拉取，早于该日期的数据不保存。
- 第一版只保存前复权日 K，不重复保存不复权和后复权行情。
- Web 页面继续通过自己的 `MarketDataProvider` 在线获取行情，不直接读取 DuckDB。
- DuckDB 的全部读、写和计算只能发生在独立 Worker 进程；Web 和未来 MCP 不得直接打开 DuckDB。
- Web 进程和 Worker 进程分别维护一个 THS 客户端。每个进程最多一个客户端，进程内调用串行，底层调用最小间隔为 50ms。
- 行情更新只保留“自动增量更新”和“强制全量更新”两种模式，均由用户在任务页面手工创建；不提供自定义日期范围。
- 两种模式的目标结束日期固定为任务创建日的前一个自然日，避免写入尚未收盘的当日日 K。thsdk 没有返回交易日数据时，以实际写入的最新交易日作为行情截止日期。
- 自动增量更新逐只股票判断：本地无数据时全量拉取；本地有数据时比较重叠前复权 K 线，未变化则增量追加，发生变化则全量重建该股票。
- 强制全量更新忽略本地状态，对任务中的每只股票重新拉取 `2025-01-01` 至目标结束日期的完整前复权日 K。
- 单只股票失败后继续处理其他股票；成功和失败并存时总任务为 `PARTIALLY_SUCCEEDED`，全部失败时为 `FAILED`。
- 部分成功任务可以创建一个新的重试任务。新任务继承原任务模式、目标结束日期，只为原任务中 `FAILED` 的股票创建 TaskItem；旧任务保持原终态。
- 外部服务不可用、数据校验失败或 DuckDB 写入失败时保存真实错误，不生成伪造行情或伪造成功结果。

### 第一版范围

- 增加 DuckDB 依赖、连接与日线 schema 管理。
- 增加全市场日线自动增量任务和强制全量任务入口。
- 在任务页面展示两个创建入口、任务进度、更新方式、实际行情截止日期和失败股票摘要。
- 每只股票对应一个 TaskItem，由现有 F002 Worker 串行执行。
- 增加失败股票业务重试入口，通过创建新任务实现，不改变通用任务终态。
- 保存日线同步状态，使 Worker 能识别本地覆盖范围和前复权口径。
- 为后续计算任务建立“仅 Worker 可访问 DuckDB”的进程边界；本 Feature 不实现具体回测或选股策略。

### 第一版非目标

- 不保存 2025-01-01 之前的行情。
- 不保存不复权、后复权、分钟 K、Tick 或 L2 行情。
- 不提供自定义开始日期或结束日期。
- 不提供定时更新、启动时更新、页面访问时更新或计算任务前隐式更新。
- 不引入多 Worker、并发子任务或同进程多个 THS 客户端。
- 不新增独立行情数据服务。
- 不允许 Web 或 MCP 同步查询 DuckDB；未来 MCP 只能复用任务创建服务。
- 不自动导出 Parquet；Parquet 备份、迁移或外部分析能力后续另行设计。
- 不实现具体回测、选股、因子或技术指标任务。

## How

### 1. 进程与数据边界

```text
FastAPI Web 进程
├── REST API
├── 未来 MCP Streamable HTTP
├── THS 客户端 A：页面在线行情
└── SQLite：任务创建、状态和结果

F002 Worker 进程
├── THS 客户端 B：持久化行情下载
├── DuckDB：历史行情读写与后续计算
└── SQLite：任务状态和结果写入
```

- 两个 THS 客户端统一通过 F004 配置加载入口读取 `data/ths_credentials.json`，构造客户端时不显式传入 MAC，由 SDK 按账号派生默认 MAC。
- thsdk 的连接、转换、50ms 限速、互斥和异常适配继续封装在 `backend/app/market_data/provider/`。
- Worker 使用 `MarketDataProvider` 获取行情，不直接调用 thsdk 或依赖 thsdk 响应对象。
- DuckDB 连接只能由 Worker 创建。Web 和 MCP 通过 SQLite 任务及结果与 Worker 协作，不把 DuckDB 连接跨进程传递。
- F002 的单 Worker 租约和串行任务模型保证行情更新任务与后续 DuckDB 计算任务不会同时访问行情库。

### 2. DuckDB 日线数据

逻辑表名为 `daily_bars`，第一版至少包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| `symbol` | `VARCHAR` | 统一股票代码，例如 `000001.SZ` |
| `trade_date` | `DATE` | 交易日期 |
| `open` | `DECIMAL(18, 2)` | 前复权开盘价 |
| `high` | `DECIMAL(18, 2)` | 前复权最高价 |
| `low` | `DECIMAL(18, 2)` | 前复权最低价 |
| `close` | `DECIMAL(18, 2)` | 前复权收盘价 |
| `volume` | `BIGINT` | 成交量，保持 thsdk 返回单位 |
| `amount` | `DECIMAL(20, 2)` | 成交额，按元保存 |

- `(symbol, trade_date)` 必须唯一。
- Python 数据进入比较和写入逻辑前先转换为 `Decimal` 并量化到两位小数，不能依赖二进制浮点直接比较价格。
- 日线表只允许保存 `adjust="forward"` 的数据。同步状态需要记录 `symbol`、固定复权口径、首个交易日、最新交易日和最后成功同步时间。
- DuckDB schema 创建和后续语义变化需要显式迁移与迁移测试；不得假定旧 master 分支的本地 DuckDB 与本 Feature schema 兼容。

### 3. 任务创建与股票范围

任务类型固定为 `market_daily_bars_update`，调度策略使用 `EXCLUSIVE_UPDATE`。

- 任务页面提供“自动增量更新”和“强制全量更新”两个按钮，不提供日期输入。
- 创建任务时把 Asia/Shanghai 当前日期的前一个自然日固化为 `target_end_date`，重试任务继承原值，不能随重试日期漂移。
- `build_items()` 从现有 SQLite 股票目录取得全市场股票，并按稳定代码顺序为每只股票创建一个 TaskItem。
- 股票目录不存在或为空时拒绝创建任务，提示用户先执行 F002.1 股票目录刷新；不得在创建请求中临时调用 thsdk 获取股票范围。
- 同类型任务已有 `PENDING`、`RUNNING` 或 `CANCEL_REQUESTED` 实例时拒绝重复创建，并返回现有任务 ID。
- FastAPI 和 Worker 启动时分别通过 `register_production_handlers()` 注册同一 Handler。Web 执行 `build_items()`，Worker 执行 `run_item()` 和 `summarize()`。

### 4. 自动增量更新

每只股票按以下流程执行：

1. 查询本地覆盖范围和最近 5 个已保存交易日。
2. 本地无数据、复权口径不是 `forward` 或无法形成有效重叠区间时，转为该股票全量更新。
3. 本地有有效前复权数据时，从最早的重叠交易日拉取到 `target_end_date` 的前复权日 K。
4. 将新旧重叠区间的 OHLC 统一量化到两位小数后比较。
5. 重叠 OHLC 完全一致时，只写入或覆盖本地最新日期之后的新增记录。
6. 任一重叠 OHLC 变化时，调用 `corporate_action()` 获取权息资料用于 TaskItem 结果和日志说明，然后从 `2025-01-01` 全量重建该股票。
7. corporate action 查询失败不能阻止已经确认必要的全量重建，但必须记录真实诊断；它用于解释变化，不作为复权变化的唯一判断依据。

重叠比较既能识别除权除息导致的历史前复权价格变化，也能识别行情源对历史价格的其他修正。只有 corporate action 日期而没有价格变化时，不主动全量刷新。

### 5. 强制全量和自动全量重建

强制全量模式以及自动增量中触发全量的单只股票使用同一条写入路径：

1. 在修改 DuckDB 前完整拉取 `2025-01-01` 至 `target_end_date` 的前复权日 K。
2. 校验股票代码、日期范围、日期严格递增、日期唯一、OHLC 必填及价格关系合法。
3. 开启 DuckDB 事务。
4. 删除该股票旧日线并插入完整新数据。
5. 核对实际行数、首个日期、最新日期和唯一性。
6. 更新同步状态并提交事务。
7. 任一步失败时回滚，保留该股票原有数据并把 TaskItem 标记为 `FAILED`。

禁止先删除旧行情再调用 thsdk，禁止全量重建失败后留下空股票或半套历史数据。

### 6. 任务结果、部分成功和重试

- 单只股票失败后继续执行后续 TaskItem，不自动重试。
- 总任务结果至少包含：任务模式、目标结束日期、全市场股票数、成功数、失败数、增量更新数、全量更新数、新增或覆盖行数、实际行情截止日期和失败摘要。
- TaskItem 结果记录股票代码、执行方式、写入行数、本地更新前后日期范围；发生复权变化时记录脱敏后的权息说明，不记录账号、密码或完整派生 MAC。
- “重试失败股票”是 F003 业务操作，不改变 F002 的通用终态规则。它以原任务 ID 创建新任务，只复制原任务中状态为 `FAILED` 的股票，保留原模式和 `target_end_date`。
- 原任务没有失败股票时拒绝创建重试任务；同一原任务已有活动重试任务时返回现有任务，避免重复执行。

### 7. 页面、Web 与未来 MCP

- Web 页面行情继续在线调用 Web 进程自己的 `MarketDataProvider`，不会因打开页面而创建更新任务。
- 任务页面展示自动增量、强制全量和部分成功后的失败股票重试入口。
- 回测和选股等后续计算任务只读取 Worker 所拥有的 DuckDB，并把使用的行情截止日期写入结果。
- 未来 MCP 与 REST API 复用同一个任务创建 service，只返回任务 ID 并查询状态，不增加 MCP 专属更新实现，也不直接访问 DuckDB。

## Acceptance Criteria

- [ ] AC1: 任务页面只提供“自动增量更新”和“强制全量更新”两个行情更新入口，不提供自定义日期范围或自动调度。
- [ ] AC2: 空行情库执行自动增量更新时，为本地股票目录中的全部 A 股创建 TaskItem，并从 2025-01-01 拉取到任务创建日的前一个自然日。
- [ ] AC3: 股票目录不存在或为空时拒绝创建行情任务，并给出先刷新股票目录的明确错误。
- [ ] AC4: 日线表只保存前复权数据，价格字段使用 `DECIMAL(18, 2)`，成交额按元使用 `DECIMAL(20, 2)`，且 `(symbol, trade_date)` 唯一。
- [ ] AC5: 本地存在有效数据且最近 5 个交易日 OHLC 未变化时，只增量写入新增日期，重复执行不会产生重复记录。
- [ ] AC6: 重叠 OHLC 发生变化时查询权息资料，并从 2025-01-01 全量重建该股票。
- [ ] AC7: 强制全量更新忽略本地状态，对任务中的每只股票使用与自动全量重建相同的事务写入路径。
- [ ] AC8: 全量拉取、校验或写入任一步失败时事务回滚，原有股票行情保持完整，TaskItem 保存真实失败原因。
- [ ] AC9: 单只股票失败不阻止后续股票执行；成功和失败并存时总任务为 `PARTIALLY_SUCCEEDED`，全部失败时为 `FAILED`。
- [ ] AC10: 部分成功任务可以创建只包含原任务失败股票的新任务，新任务继承原模式和目标结束日期，旧任务终态不变。
- [ ] AC11: Web 和 Worker 各自最多持有一个 THS 客户端，调用串行且底层调用间隔不小于 50ms；客户端统一读取 F004 配置并使用 SDK 默认派生 MAC。
- [ ] AC12: DuckDB 只由独立 Worker 进程打开；Web、页面请求和未来 MCP 均不能直接访问 DuckDB。
- [ ] AC13: Web 在线行情不触发行情持久化更新，页面打开、后端启动和后续计算任务均不隐式创建更新任务。
- [ ] AC14: 行情更新 Handler 通过统一入口分别注册到 Web 和 Worker，Web 可以构建全市场子任务，Worker 可以执行和汇总同一 `task_type`。
- [ ] AC15: 任务及子任务结果不包含同花顺账号、密码或完整派生 MAC，外部服务失败时不生成伪造行情。
- [ ] AC16: 总任务结果包含模式、目标日期、成功/失败股票数、增量/全量股票数、写入行数及实际行情截止日期。
- [ ] AC17: DuckDB schema 和同步语义具有迁移方案与迁移测试，不静默复用不兼容的旧数据库。
- [ ] AC18: 后端自动化测试通过，任务页面相关前端生产构建通过。

## Risk

| 风险 | 解决 |
|------|------|
| 新除权除息使既有前复权历史整体变化 | 每次增量请求包含最近 5 个本地交易日；重叠价格变化时全量重建该股票 |
| 为全市场逐只调用权息接口显著增加请求时间 | corporate action 只在重叠价格变化后调用，不作为每次更新的前置请求 |
| 全量重建失败导致股票历史被清空 | 先完整拉取和校验，再在单个 DuckDB 事务中替换；失败回滚 |
| Web 与 Worker 同时打开 DuckDB 导致文件锁冲突 | DuckDB 由 Worker 独占，Web/MCP 永不直接连接 |
| Web 与 Worker 的 THS 客户端发生限频或原生库冲突 | 每进程一个客户端，进程内串行并统一执行 50ms 最小间隔 |
| 正式账号多进程长期稳定性仍未完全证明 | 已完成两轮短时双进程验证；保留真实连接错误并在实现后执行长任务验证 |
| 当日未收盘行情进入历史库 | 目标结束日期固定为任务创建日的前一个自然日，并记录实际行情截止日期 |
| 失败股票重试改变原任务历史 | 重试始终创建新任务并关联原任务，旧任务保持终态 |
| 旧 master DuckDB 或其他本地文件 schema 不兼容 | 新 Feature 使用显式 schema 检查和迁移，不直接复用未确认数据语义 |
| 大型全市场任务阻塞后续计算任务 | 沿用 F002 单 Worker 串行队列并展示进度；第一版接受该取舍 |
